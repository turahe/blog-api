# Media Management

## Scope

- secure file upload
- file listing and deletion
- metadata tagging
- native support for R2 and S3-compatible object storage
- on-the-fly image resizing and format conversion
- tiered transformed-image caching
- relational associations for avatars, post attachments, and category covers via media_assets references

## Functional Requirements

- uploads must validate file type and size
- uploads must pass malware scanning before finalization
- media metadata must be queryable for admin use
- transformed image endpoints must support width, height, fit, rotate, quality, and output format
- resized variants must be generated dynamically, not pre-generated by default
- media deletion must respect FK references:
  - `users.avatar_id` -> SET NULL
  - `categories.image_id` -> SET NULL
  - `posts.cover_image_media_id` -> SET NULL
  - `post_media` rows -> CASCADE or explicit cleanup depending on policy

## Supported Storage Providers

- Cloudflare R2
- AWS S3
- MinIO
- DigitalOcean Spaces
- other S3-compatible services with the same configuration model

## Performance Expectations

- cache hot transforms aggressively
- avoid repeating the same transform work unnecessarily
- define latency budgets for common image sizes in testing
